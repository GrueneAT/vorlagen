Strategy summary

Die vier Alt-Aufnahmen auf /anleitung/ weichen zwei Neuaufnahmen im aktuellen Design. Die Richtung: ein Array-Austausch in videos.ts — alles Weitere ist bereits datengetrieben gebaut und zieht automatisch nach. Zwei Folgeaenderungen muessen im selben Change mitlaufen, sonst laufen Build und CI auseinander.

  • Daten statt Markup.

    Der Hinweis „im alten Design aufgenommen“ haengt an videos.some(v => v.legacyDesign). Faellt das Flag weg, verschwindet er von selbst — VideoGrid.astro und VideoModal.astro bleiben unangetastet.

  • Laufzeiten sind verifiziert.

    14:38 und 8:39, aus den YouTube-Watch-Seiten (lengthSeconds 878 bzw. 519). Die offene LOW-confidence-Frage der Recherche ist damit beantwortet; die Felder werden gesetzt, nicht weggelassen.

  • Build allein ist truegerisch gruen.

    Der Guard-Test test_site_anleitung_content.py ist hart auf die vier alten IDs gekoppelt und failt beim Wegfall von legacyDesign absichtlich. Verifikation faehrt Build UND pytest tests/unit/ wie CI.

02Flow

Task flow & dependencies

Task 1 videos.ts auf die zwei neuen Scribus-Videos umstellen Array-Austausch, kein legacyDesign, Laufzeiten 14:38 / 8:39.
Task 2 Guard-Test auf die zwei neuen Video-IDs umstellen EXPECTED_VIDEO_IDS neu, Legacy-Test entfernen — loest den roten Zwischenzustand aus Task 1.
Task 3 Video-Grid auf auto-fit mit Kartenobergrenze umstellen repeat(auto-fit, minmax(220px, 320px)) statt auto-fill.
Task 4 Gesamtverifikation gegen die Akzeptanzkriterien Build, CI-Testlauf und HTML-Assertion auf /anleitung/ plus Detailseite.

03Decisions

Key decisions & options

Legacy-Hinweis im Markup

Chosen

Stehen lassen — ISSUE.md erlaubt das ausdruecklich, der Block rendert ohne legacyDesign einfach nicht mehr. Auch das Interface-Feld bleibt erhalten.

Markup und Interface-Feld loeschen — unnoetiger Diff, wirft eine bewusst gebaute Faehigkeit weg.

Grid-Layout bei nur zwei Karten

Chosen

repeat(auto-fit, minmax(220px, 320px)): auto-fit kollabiert leere Spuren, die Obergrenze verhindert auseinandergezogene Karten auf breiten Viewports.

auto-fit mit 1fr — zwei Karten werden auf Ultrawide uebergross. Festes repeat(2, ...) — bricht die responsive Logik der Datei.

duration setzen statt weglassen

Abweichung von RESEARCH.md

Die Recherche empfahl Weglassen mangels verlaesslicher Quelle. Inzwischen sind beide Werte verifiziert (878s / 519s) — die Karten behalten damit ihre bisherige Informationsdichte.

Testrunner-Umfang

Fallstrick

Verifiziert wird mit /root/.local/bin/pytest (nicht auf dem Standard-PATH), exakt wie CI: tests/unit/ -q --ignore=tests/unit/test_idml_strict_mode.py.

Zusaetzliches unittest discover auf tests/unit — die Datei importiert pytest auf Modulebene; unittest laeuft in diesem Repo nur gegen tools/sla_lib/tests.
